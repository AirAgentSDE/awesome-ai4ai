# AI4AI 周报 · 2026-W37（基线特刊：Auto-Research 三年脉络 2023–2026）

> 覆盖范围：2023-01 ~ 2026-09（基线建立期）
> 本期为**发刊基线**：按「从可 hack 底座出发到自动科研闭环」主线建立三年全景。后续周报只收录增量（过去一周的新项目/论文），不再重复本期条目。

## 本周落点

本期是基线特刊，条目覆盖主线全部六环。三年演进的整体判断：**2023–2024 年各环独立成熟（基准、自博弈、合成数据、训练框架），2025 年端到端闭环系统集中出现并受到严格评测，2026 年 karpathy/autoresearch 把闭环压缩到 630 行，范式开始向「任意可度量指标」泛化**——主线的终点（闭环）反过来定义了起点（底座）的形态。

- **项目链接**：https://github.com/karpathy/nanoGPT ｜ https://github.com/karpathy/nanochat ｜ https://github.com/karpathy/llm.c
- **论文 | 技术报告**：—

### 底层 Infra 封装 + 灵活训练 API

#### Tinker（+ Cookbook）

- **项目链接**：https://github.com/thinking-machines-lab/tinker-cookbook

#### Twinkle

- **项目链接**：https://github.com/modelscope/twinkle

- **卖点**：接口为 Tinker API 的超集并向后兼容——TaaS 层开始出现事实接口标准；100 行内可定制 RL 训练。

#### OpenRL / OpenRLHF

- **项目链接**：https://github.com/OpenRL-Lab/openrl ｜ https://github.com/OpenRLHF/OpenRLHF

- **出处**：第四范式 / OpenRLHF 社区
- **卖点**：RL 训练从论文代码走向可复用 infra，是自进化方法能规模化实验的前提。

## 评测

### MLAgentBench（2023）

- **项目链接**：https://github.com/snap-stanford/MLAgentBench
- **论文 | 技术报告**：arXiv:2310.03302（NeurIPS 2023 D&B）
- **一句话描述**：衡量 agent 跑通 ML 实验全流程（读代码、改模型、跑实验）的早期基准。
- **出处**：Stanford
- **卖点**：把「agent 做 ML」变成可量化问题的起点，后续 MLE-bench/PaperBench 的先行者。

### MLE-bench（2024）

- **项目链接**：https://github.com/openai/mle-bench
- **论文 | 技术报告**：arXiv:2410.07095
- **一句话描述**：75 个真实 Kaggle 竞赛任务，衡量 agent 的端到端 ML 工程能力。
- **出处**：OpenAI
- **卖点**：以 Kaggle 奖牌为外部标尺，结果可直接与人类参赛者比较。

### PaperBench（2025）

- **项目链接**：https://github.com/openai/preparedness
- **论文 | 技术报告**：arXiv:2504.01848
- **一句话描述**：要求 agent 从零复现 20 篇 ICML 2024 Spotlight/Oral 论文的长程基准。
- **出处**：OpenAI
- **卖点**：8,316 个与原作者共建的层级化 rubric 节点 + LLM 裁判；最强 agent 复现得分 21.0%，显著低于博士基线 41.4%——为闭环系统立下「尚未逾越」的标尺。

### PostTrainBench（2026）

- **项目链接**：https://github.com/aisa-group/PostTrainBench
- **论文 | 技术报告**：见仓库
- **一句话描述**：衡量 CLI agent 在给定算力预算（单卡 10 小时）内自动完成后训练任务的能力。
- **出处**：aisa-group
- **卖点**：评测对象从「做题」转向「训练模型」，直接考核闭环主线的中间环节。

### autoresearch（2026.03）

- **项目链接**：https://github.com/karpathy/autoresearch
- **论文 | 技术报告**：—
- **一句话描述**：630 行 Python 的自主研究循环——agent 修改 train.py、5 分钟训练、按 val_bpb 决定保留/回滚，永不停止。
- **出处**：Karpathy

## Recommended Stacks

面向个人开发者 / 单卡场景，能跑通完整闭环的最小组合：

| 环节 | 选择 | 理由 |
| --- | --- | --- |
| 底座 | nanochat（或 autoresearch 自带 train.py） | 全栈最小实现，agent 可完整读懂并修改 |
| 训练 | 本地：Unsloth / LLaMA-Factory；托管：Tinker 或 Twinkle（接口兼容） | 本地零成本起步，托管免去分布式运维 |
| 数据 | distilabel / Magpie 合成 + data-juicer 清洗 | 合成与筛选两段式管线 |
| 评测 | lm-evaluation-harness + PostTrainBench | 通用能力 + 后训练实操双层验证 |
| 闭环编排 | karpathy/autoresearch 的 program.md + train.py 模式 | 630 行可审查，Git 做版本控制 |

适用场景：单卡（H100 最佳，TinyStories 等小配置可降门槛）跑无人值守的 post-training 研究实验；想自定义领域时，核心工作是替换「一个文件 + 一个指标」。

## Trends

1. **闭环形态收敛**：「一个文件 + 一个指标 + 固定时间预算」成为自主研究循环的最小事实形态，karpathy/autoresearch 一周 3.7 万星说明社区已用 star 投票。
2. **范式泛化加速**：从 LLM 训练扩散到 GPU kernel（AutoKernel）、智能合约 gas 优化（pi-autoresearch 案例）乃至任意可度量指标；迁移成本集中在指标定义。
3. **代理指标风险浮现**：arXiv:2607.18064 指出 autoresearch 循环交给 agent 的是「可被利用的代理指标」，区分 generalizer 与 metric-maximizer 会成为闭环评测的新维度。
4. **训练层向 TaaS 收敛**：Twinkle 兼容 Tinker API，训练接口出现事实标准的早期信号——agent 调用训练能力将像调用推理 API 一样自然。
5. **评测焦点迁移**：从「完成指定任务」（SWE-bench/MLE-bench）转向「长程复现与自主迭代」（PaperBench/PostTrainBench），且开始考核训练实操而非仅代码修补。
6. **人类角色上移**：从执行者变为系统设计者——定义「什么叫好」（评估标准）与「在什么范围内探索」（探索空间）成为人不可替代的贡献。
